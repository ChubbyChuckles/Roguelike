Skill Creation Suite - Effect Tree Authoring & Validation Enhancements
---------------------------------------------------------------------
Summary:
Adds authoring-time validation for SPAWN_ENTITY parameters, overlay UI editing for experimental effect tree nodes, JSON debug override round-trip support, and two focused unit tests (hierarchical scheduling + cycle rejection) to harden the new feature.

Details:
* Validation: Enforce SPAWN_ENTITY count [1..8] and life_ms > 0 across primary effect, legacy flat effect nodes, and effect_tree nodes in skills_validate.
* Serialization: Debug overrides exporter/importer now persist an `effect_tree` array (skipped when empty) enabling round‑trip editing without losing hierarchical data.
* Overlay UI: Panel exposes a "Use Effect Tree" toggle; when enabled, allows editing node count and per-node fields (effect_spec_id, delay_ms, duration_ms, repeat_count, repeat_interval_ms, HP gate, parent_index) with bounds guardrails.
* Tests: Added test_skills_phase1_2_effect_tree_schedule (verifies parent-relative delays + periodic window + chained grandchild) and test_skills_phase1_2_effect_tree_cycle (ensures cycle detection rejects invalid parent graphs).
* Build Fix: Resolved pointer type warning (treated as error) in skill_debug.c effect_tree serialization loop by using RogueSkillEffectTreeNode*.
* README: Updated effect tree bullet to reflect completed UI + export/import integration and strengthened validation (including SPAWN_ENTITY constraints).

EffectSpecs: SPAWN_ENTITY effect (Phase 1.2 slice)

- Add ROGUE_EFFECT_SPAWN_ENTITY enum value with two fields: spawn_entity_count (u8, clamped 1..8, default 1) and spawn_entity_life_ms (float ms, default 5000 if <=0).
- Parser & JSON loader accept `spawn_entity_count` and `spawn_entity_life_ms` keys (ignored for other kinds).
- Runtime apply: spawns N transient entities at caster position using lightweight fixed-cap (64) pool in spawn_entities.c; each entry stores x,y, expiry_ms and auto-expires on update.
- Sanitization during apply ensures safe defaults even if authoring omitted or out-of-range values.
- Unit: test_effectspec_spawn_entity (ensures counts increment and return to 0 after advancing time beyond lifetime).
- Roadmap (skill creation suite) updated: mark SPAWN_ENTITY done with implementation blurb; README EffectSpec JSON reference documents new fields and semantics.

Advanced Effect Validation (Phase 1.2 completion)
-----------------------------------------------
* Added advanced heuristics to rogue_skills_validate_all:
	- Non-negative delay_ms for flat and tree nodes.
	- repeat_interval_ms > 0 required when repeat_count > 0.
	- duration_ms must cover repeat_count * repeat_interval_ms when both provided.
	- Global effect tree scheduled span cap (<= 60000ms) computed from chained delays + window/repeat span; rejects runaway authoring.
* New unit: test_skills_phase1_2_effect_tree_advanced_validation (fails insufficient window, fails span overflow, passes valid composition).
* Roadmap: Marked "Advanced Effect Validation" complete with heuristic list.
* README: Updated Recent Skills/Effects section to list new validation rules.

Advanced State Machine & Skill Queuing (Phase 1.3 slice)
-------------------------------------------------------
* Added queued skill execution state (ROGUE_SKEXEC_QUEUED) and global lockout scaffold (ROGUE_SKEXEC_GLOBAL_LOCKOUT future use) in skills.h.
* Introduced rogue_skill_request API enabling buffered activation attempts; falls back to immediate activation and, on failure (cooldown/casting conflict), schedules using existing queued_trigger_ms/queued_until_ms with input_buffer_ms window.
* Extended RogueSkillState with queued_active flag; activation state accessor now reports queued state.
* Runtime processes queued activations immediately after a casting skill completes (reusing existing loop) and clears queued state.
* Added unit test test_skills_phase1_3_advanced_state_machine validating mid-cast queue then automatic post-cast firing and queue clearing.
* Roadmap: Marked Advanced State Machine & Skill Queuing System tasks complete with implementation notes.
* README: Added brief bullet in Skills Execution section describing queued activation support and new API.
* Non-invasive: Does not alter existing activation semantics for instant skills lacking input_buffer_ms (no regression risk).
