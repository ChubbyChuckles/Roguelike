# PIXEL-PERFECT COLLISION SYSTEM & DEBUG OVERLAY IMPLEMENTATION PLAN
## ADVANCED TECHNICAL ARCHITECTURE & GRANULAR IMPLEMENTATION

### EXECUTIVE SUMMARY
This sophisticated implementation plan details the complete replacement of the current ball-shaped hitbox collision system with a state-of-the-art pixel-perfect collision detection framework. The system incorporates advanced optimization techniques, comprehensive debugging tools, and maintainable architecture patterns to achieve sub-5ms collision detection performance while providing rich debugging capabilities.

### TECHNICAL ARCHITECTURE OVERVIEW
```
┌─────────────────────────────────────────────────────────────────┐
│                    PIXEL-PERFECT COLLISION SYSTEM               │
├─────────────────────────────────────────────────────────────────┤
│  Input Layer: SDL2 Sprites → Pixel Data Extraction             │
│  Processing: Multi-Stage Collision Pipeline                     │
│  Output: Hit Events + Debug Visualization Data                  │
└─────────────────────────────────────────────────────────────────┘

Core Subsystems:
├── Pixel Mask Generation Engine (PNG/BMP → Collision Masks)
├── Multi-Resolution Collision Detection (3-tier accuracy system)
├── Spatial-Temporal Optimization Engine (Quadtree + Temporal Coherence)
├── Real-Time Debug Visualization Framework (ImGui-style overlay)
├── Performance Profiling & Analytics Engine
└── Asset Pipeline Integration & Hot-Reload System
```

### CURRENT SYSTEM DETAILED ANALYSIS
#### Existing Collision Architecture
- **Primary System**: `src/game/hit_system.c` - Capsule-based collision with 640ms average processing time
- **Data Structures**: `RogueCapsule` with radius-based overlap testing
- **Enemy Processing**: Linear scan through `ROGUE_MAX_ENEMIES` with AABB pre-filtering
- **Hit Feedback**: `src/game/hit_feedback.c` with particle system integration
- **Performance Profile**: ~2-3ms per frame with 10-15 enemies, degrades quadratically

#### Pixel Mask Foundation Assessment
- **Existing Code**: `src/game/hit_pixel_mask.{h,c}` - Basic structures defined, incomplete implementation
- **Data Format**: 32-bit word-packed bitfields with configurable pitch
- **Current Limitations**: No sprite loading, placeholder mask generation only
- **Memory Layout**: Row-major bit packing, ~1KB per 64x64 mask

#### Item System Integration Points
- **Definition Storage**: `src/core/loot/loot_item_defs.c` - 512 max items with sprite references
- **Sprite Fields**: `sprite_sheet[128]`, `sprite_tx/ty/tw/th` for atlas coordinates
- **Loading Pipeline**: JSON and CFG file support via `rogue_item_defs_load_from_json()`
- **Runtime Access**: `rogue_item_def_at()` and handle-based lookups

#### Debug Framework Assessment
- **Panel System**: `src/debug_overlay/overlay_core.c` - 32 max panels with SDL2 rendering
- **Widget Library**: Comprehensive UI controls in `src/debug_overlay/widgets/`
- **Rendering Backend**: Direct SDL2 primitives with theme support
- **Input Handling**: Mouse/keyboard with focus management
