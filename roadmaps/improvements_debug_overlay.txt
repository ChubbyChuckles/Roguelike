DEBUG OVERLAY UI/UX IMPROVEMENTS PLAN (Authoring-first, Modern UX)

Context and constraints
- Runtime: SDL2 renderer/input, immediate-mode UI in C, headless-safe APIs, MSVC toolchain (no VLAs; compile-time constants only).
- Existing: Panels for System, Skills, Items, Entities, Map, Audio/VFX; Content Graph visualization with exports; validation manager; JSON schemas and round-trips; live reload.
- Primary goal: Make adding/editing all asset types fast, safe, and pleasant while keeping overlay performance high and headless tests stable.

Guiding principles
- Authoring-first: Minimize clicks and modality. Offer smart defaults, templates, and fix-it actions.
- Always in context: Inline validation, previews, and references near the editor controls.
- Keyboard-first: Every action has a shortcut; full focus traversal with clear affordances.
- Non-blocking: Background I/O with progress; errors surface as toasts, not modal stops.
- Style consistency: Single theme system controls spacing, colors, typography, and DPI.

Implementation notes and constraints
- MSVC: use compile-time caps (e.g., OVERLAY_*_MAX_*) for buffers; avoid VLAs. Ensure declaration-before-statement compliance in C sources; panel_skills_effects.c adjusted by moving typedefs/static state to the top of the relevant block.
- Input: prefer “clicked” over “pressed” for discrete actions; capture input on focus.
- Headless: keep logic separated from rendering; all commands callable without SDL.
- Filesystem: atomic writes; centralize save paths; per-test isolation for units.
- Style: no hard-coded literals in panels—only through overlay_theme.

Acceptance criteria summary
- All major asset types can be created/edited/saved without touching raw JSON.
- Global search/command palette navigate anywhere within 1–2 keystrokes on average.
- Validation is always visible and fixable in-place; no modal dead-ends.
- Overlay remains responsive (>60 FPS) on large content sets; heavy work off-thread.
- Theming and shortcuts are consistent; settings persist; headless tests cover core flows.

Risk and mitigations
- Large content sets: use virtualized lists and incremental search; paginate when needed.
- Windows mtime quirks: keep existing robust mtime helpers; add backoff on save/reload.
- Visual complexity: ship with sensible defaults and progressive disclosure (collapsibles).
- Tech debt: codify UI constants early (overlay_theme); avoid ad-hoc styles.
